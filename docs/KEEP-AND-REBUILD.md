
FAMILY INVESTING CLUB
Keep + Rebuild UX Specification
How the strongest FTA systems should be retained, reorganized and redesigned inside the new warm, beginner-first, family-first, white-label FIC experience.
Core rule: preserve mature engines and workflows; rebuild the member-facing hierarchy, visual language and learning journey. FIC should feel new without throwing away the expensive systems that already work.
 | 
1. What We Are Keeping
The existing FTA codebase already contains much more than an LMS. The current-state inventory shows learning, practice, family, community, research, AI, live programming, progress, membership, CRM and admin systems. The redesign should preserve these engines while changing how members experience them.

 | 2. New Member Navigation
The retained systems should not each become a permanent tab. FIC needs a simple beginner mental model:
HOME  •  LEARN  •  MARKETS  •  CLUB  •  PROFILE
Practice, Family and Kai are major systems but can be entered contextually from these five surfaces. On desktop they can also appear in secondary navigation. For school/partner tenants, navigation can be recomposed around Classes, Assignments and Students while using the same engines.
3. Member-Facing UX
3.1 Home
Purpose. Give every learner a clear answer to “what should I do today?”
UX. Warm personalized dashboard led by Continue Learning, daily goal/streak and one clear next action. Below that: family progress, practice activity, market lesson of the day, followed Club ideas and upcoming live sessions. It should feel like a guided journey rather than a dashboard of equal cards.
Keep from FTA. Existing persona-aware home data, progress, live events, market pulse, community activity, challenge state and family state.
Rebuild for FIC. Prioritize learning. Reduce market-terminal density. Use progressive disclosure so beginners see a few meaningful items, not every capability at once.
Connects to. Learn, Practice, Family, Club, Live Classes.
3.2 Learn - Learning Path
Purpose. Turn the existing course catalog into a visible progression from beginner to competent investor/trader.
UX. Users see paths such as Money Basics, Investing 101, Stocks & ETFs, Portfolio Building, Company Analysis, Technical Analysis and Trading. Each path shows lesson nodes, checkpoints, mastery and locked prerequisites.
Keep from FTA. Existing courses, modules, lessons, quizzes, skill data and LessonEngine.
Rebuild for FIC. Replace catalog-first browsing as the default with journey-first progression. Course catalog can remain available under Browse/Library.
Connects to. Lesson Player, Flashcards, Games, Missions, Progress.
3.3 Lesson Player / Video LMS
Purpose. Deliver structured lessons using video, text, graphics and interaction.
UX. A lesson opens with a simple objective and estimated time. Video should be one component, followed by interactive checks, examples, definitions and a short application activity. Progress is persistent. Users can ask Kai about the exact lesson without leaving it.
Keep from FTA. Existing LessonEngine, FTA course player, lesson completion and video/course infrastructure.
Rebuild for FIC. Make lessons shorter, warmer and more interactive. Avoid long-video-only learning. Add concept mastery, inline quizzes, visual examples and age/level variants.
Connects to. Quiz, Flashcards, Kai, Practice activity, next lesson.
3.4 Course / Video Library
Purpose. Preserve long-form classes, workshops and deeper programs that do not fit the bite-size path.
UX. Browse by path, level, topic, instructor and program. Each course has progress, description, modules and resume state. This is a secondary library, not the primary Learn home.
Keep from FTA. FTA course library and shared course catalog.
Rebuild for FIC. Rebrand away from FTA assumptions and make every course tenant/program aware.
Connects to. Learning Path, Live Classes, Recordings.
3.5 Live Classes
Purpose. Give families, learners and institutions access to scheduled instruction.
UX. Tabs for Live Now, Upcoming and Recordings. Upcoming sessions show topic, instructor, level, date/time and add/remind action. Live sessions can link to a lesson/path and produce a recording afterward.
Keep from FTA. Existing Live Now / Upcoming / Recordings system and admin live-session management.
Rebuild for FIC. Warm event presentation; connect each session to curriculum and family/classroom context.
Connects to. Home, Courses, Notifications, Recordings, Club Live.
3.6 Recordings
Purpose. Make past live instruction searchable and useful rather than an archive dump.
UX. Filter by topic, instructor, learning path and date. Resume playback. Show concepts covered and related lessons.
Keep from FTA. FTA recordings and completed live-session archive.
Rebuild for FIC. Generalize to FIC/tenant recordings and attach metadata/concepts.
Connects to. Live Classes, Video LMS, Learn.
3.7 Flashcards / Review
Purpose. Help users retain terminology and concepts.
UX. Quick review sessions generated from completed lessons and weak concepts. Users swipe/answer, rate confidence and earn modest XP.
Keep from FTA. Existing flashcard study sets.
Rebuild for FIC. Make review adaptive and connected to mastery rather than a disconnected study tool.
Connects to. Learn, Progress, Kai.
3.8 Games Hub
Purpose. Make financial learning fun through short skill drills.
UX. A visually dynamic Practice area with game categories: investing games, chart games, recognition drills, decision exercises and family/class challenges. Each game shows skill, level, time and best score.
Keep from FTA. Existing /games practice hub and XP/progress systems.
Rebuild for FIC. Elevate from miscellaneous games into a major FIC differentiator. Keep it sophisticated enough for adults and teens; playful, not childish.
Connects to. Practice, Learn, Progress, Challenges.
3.9 Chart Practice
Purpose. Teach chart reading and pattern/setup recognition without risking money.
UX. Users receive a chart with controlled information, answer a prompt or predict the next move, reveal outcome, then receive an explanation. Difficulty rises with mastery.
Keep from FTA. Existing /chart chart-practice system.
Rebuild for FIC. Wrap drills in clear learning objectives and feedback; integrate with technical-analysis curriculum.
Connects to. Games, Technical Analysis path, Simulator.
3.10 Practice Investing / Simulator
Purpose. Let users apply investing and trading concepts with virtual money.
UX. Practice Portfolio clearly labeled as simulated. Users search securities, place simulated orders, view holdings/P&L/equity curve and receive educational prompts. Beginners get simpler order flows; advanced learners can unlock more complexity.
Keep from FTA. Existing paper-trading simulator, positions, trades, P&L, performance and trade history.
Rebuild for FIC. Do not make it look like a real-money brokerage. Add learning interventions, thesis prompts, diversification feedback and family/class portfolio modes.
Connects to. Markets, Scenarios, Challenges, Family, Club model portfolios.
3.11 Scenario Lessons
Purpose. Teach decision-making through guided market situations.
UX. Present a realistic situation, allow the learner to choose an action, advance the scenario, then review consequences and reasoning. Scenarios can be historical or simulated.
Keep from FTA. Existing /simulator/lessons guided scenarios.
Rebuild for FIC. Connect scenarios to curriculum mastery and use warmer narrative/visual presentation.
Connects to. Simulator, Simbot, Learn.
3.12 Simbot
Purpose. Coach learners through simulations.
UX. Conversational assistant inside practice scenarios that asks what the learner sees, challenges reasoning, gives hints and explains outcomes.
Keep from FTA. Existing guided simulation assistant.
Rebuild for FIC. Reposition as a learning coach and potentially unify its intelligence layer with Kai while preserving simulation-specific behavior.
Connects to. Simulator, Scenarios, Kai.
3.13 Missions / Challenges
Purpose. Create applied assignments that move learning outside passive lessons.
UX. Individual, family and class challenges can ask users to research a company, build a diversified portfolio, identify a chart pattern, explain a concept or complete a family investing-night activity.
Keep from FTA. Existing missions, kid/family missions, challenge progress and challenge infrastructure.
Rebuild for FIC. Separate educational missions from the old acquisition challenge funnel. Make challenges reusable by families, teachers and tenants.
Connects to. Family, Classroom, Games, Club, Progress.
3.14 Progress / Achievements
Purpose. Make growth visible and motivating.
UX. Show XP, streak, level, path completion, mastery by skill, badges, credentials and recent wins. A learner should understand both activity and actual competence.
Keep from FTA. Existing XP, progress, badges/credentials and leaderboard systems.
Rebuild for FIC. Emphasize mastery alongside XP. Use warm celebrations and avoid making financial education feel like empty point farming.
Connects to. Home, Learn, Family, Profile.
3.15 Leaderboards
Purpose. Add friendly motivation within appropriate groups.
UX. Family, class/cohort and optional community standings. Filters by weekly XP, challenge score or specific game. Cooperative family goals should exist alongside competition.
Keep from FTA. Existing individual/family XP standings and family leaderboard.
Rebuild for FIC. Default to relevant small-group competition rather than one giant global leaderboard.
Connects to. Family, Classes, Games, Challenges.
3.16 Markets / Company Discovery
Purpose. Help beginners explore real companies and connect market data to what they are learning.
UX. Search companies, ETFs and concepts. Curated categories and beginner-friendly discovery sit above advanced filtering. Results explain why a company matched rather than only showing ticker data.
Keep from FTA. Existing Discover, screener/Stock Finder, market data, logos, quotes and saved screens.
Rebuild for FIC. Simplify the default experience; keep advanced filters for power users. For FIC the label can be Markets while tenant terminology remains configurable.
Connects to. Ticker/Company Page, Watchlists, Learn, Kai.
3.17 Company / Ticker Page
Purpose. Turn a stock page into an educational company dossier.
UX. Start with company identity, price/chart and plain-language business summary. Sections explain how the company makes money, key metrics, recent news, community ideas and practice actions. Financial terms are tappable for explanations.
Keep from FTA. Existing ticker research with charts, fundamentals, social, debate, Kai and news.
Rebuild for FIC. Move from decision-room/trader framing to beginner comprehension and guided analysis. Preserve deeper data behind expandable sections.
Connects to. Markets, Learn, Practice, Club, Kai.
3.18 Watchlists / Research Lists
Purpose. Let users save companies and organize research.
UX. Personal, family and class lists. Each item can carry a reason for watching, notes and related investment idea. Family lists can become research assignments.
Keep from FTA. Existing private/household watchlist and community research board.
Rebuild for FIC. Reframe from trading watchlist toward learning/research lists while retaining price tracking.
Connects to. Markets, Family, Club, Practice.
3.19 News
Purpose. Help beginners understand market events rather than consume a raw financial-news feed.
UX. Stories are grouped around followed companies, learning concepts and major market events. Each story can offer 'Why this matters' and linked definitions/lessons.
Keep from FTA. Existing market newsroom and news detail pages.
Rebuild for FIC. Make contextual explanation more important than volume of headlines.
Connects to. Markets, Company pages, Learn, Kai.
3.20 Club Home / Feed
Purpose. Create the collective investing-learning environment promised by the Family Investing Club name.
UX. Feed mixes structured Investment Ideas, company research, questions, polls, model-portfolio updates, challenges and live sessions. Filters allow Ideas, Following, Groups and Live. Educational quality outranks raw posting volume.
Keep from FTA. Existing Feed, Lounge, Live, profiles, reactions, debates, mentions and real-time chat.
Rebuild for FIC. Rebuild around structured investing objects. Generic posts remain possible but should not dominate.
Connects to. Investment Ideas, Groups, Model Portfolio, Live, Profiles.
3.21 Investment Idea / Thesis
Purpose. Let members collectively research an opportunity in a disciplined format.
UX. An idea contains thesis, companies/assets, why it matters, risks, time horizon, evidence, conviction/status and updates. Members follow, discuss, save companies, join research and launch linked concept lessons.
Keep from FTA. Existing structured thesis detail, research objects and debate/social systems.
Rebuild for FIC. Make thesis creation beginner-friendly with prompts/templates and preserve history as the thesis evolves.
Connects to. Club, Company pages, Watchlists, Model Portfolio, Learn.
3.22 Groups / Family / Classroom Communities
Purpose. Support smaller collective-learning spaces.
UX. Private family groups, classroom groups, institution communities and topic-based investing groups. Each group has feed, members, pinned resources, challenges and optional model portfolio.
Keep from FTA. Existing community/social infrastructure, family membership and real-time chat.
Rebuild for FIC. Generalize permissions and visibility for multi-tenant use. Youth access must be role/age aware.
Connects to. Club, Family, Classes, Challenges.
3.23 Club Model Portfolio
Purpose. Allow collective investing decisions to be practiced transparently without pooling member money.
UX. Show simulated/model holdings, weights, benchmark, performance, thesis for every holding and change history. Members can discuss proposals and, when enabled, vote.
Keep from FTA. Existing practice/simulation engine, community research objects and community watchlist provide reusable foundations; the source inventory does not show a complete model-portfolio voting product, so this portion is an FIC expansion.
Rebuild for FIC. Build as an educational model portfolio, clearly separated from real customer assets.
Connects to. Investment Ideas, Practice, Groups, Learn.
3.24 Community Chat / Lounge
Purpose. Support real-time conversation around classes, ideas and markets.
UX. Topic rooms and group chat with replies, mentions and links to structured objects. A chat message can reference a company, lesson or idea rather than becoming isolated text.
Keep from FTA. Existing Lounge, real-time chat, mentions and FTA traders-room infrastructure.
Rebuild for FIC. Use selectively; do not let chat replace structured research. Tenant/community moderation is required.
Connects to. Club, Groups, Live.
3.25 Family Hub
Purpose. Make the household itself an investing-learning team.
UX. Family overview shows members, shared streak, weekly challenge, each person's learning progress, family research list and practice portfolio. Parents can manage profiles and see progress without impersonating children.
Keep from FTA. Existing Family hub, overview, members, leaderboard, missions, family watchlist and age-aware experiences.
Rebuild for FIC. Elevate Family from a mode into a first-class FIC differentiator. Add weekly Family Investing Night prompts and clearer parent controls.
Connects to. Home, Learn, Practice, Club, Progress.
3.26 Family Members / Parent View
Purpose. Manage household access and understand each learner's progress.
UX. Parent sees profile level, current path, streak, recent activity, mastery needs and assigned family tasks. Add/invite/manage members from one place.
Keep from FTA. Existing household member management and family CRM data.
Rebuild for FIC. Improve guardian controls and make child progress understandable rather than admin-like.
Connects to. Family Hub, Progress, Settings.
3.27 Kai - Investing Tutor
Purpose. Give learners contextual help without forcing them to leave what they are doing.
UX. Kai can explain a concept, simplify language, quiz the learner, explain a chart, help research a company or summarize arguments around a community idea. Contextual Kai opens as a lightweight sheet; a fuller tutor workspace can exist under Profile/More if needed.
Keep from FTA. Existing Kai chat/deep mode, research reports, user memory and contextual AI capabilities.
Rebuild for FIC. Shift the default personality from trading copilot to patient investing tutor. Ground responses in lesson progress, learner level, market context and FIC content.
Connects to. Lessons, Markets, Practice, Club, Family.
3.28 Public / Member Profile
Purpose. Give community members a learning and contribution identity.
UX. Profile can show bio, learning level, badges/credentials, favorite companies, followed ideas and approved community contributions. Youth privacy defaults should be stricter.
Keep from FTA. Existing public profiles, favorites, picks, credentials, age/role badges and mentions.
Rebuild for FIC. Center learning/research reputation rather than trading performance.
Connects to. Club, Progress, Referrals.
3.29 Referrals
Purpose. Let families and members invite others while tracking advocacy.
UX. Simple share link, invited/joined families and earned rewards/XP. Institutional tenants can disable or customize it.
Keep from FTA. Existing measurable referral links, joined-family stats and XP.
Rebuild for FIC. Warm family invitation framing; keep out of primary navigation.
Connects to. Profile, CRM.
3.30 Settings / Billing / Notifications
Purpose. Handle account configuration without cluttering the learning experience.
UX. Profile identity, family membership, appearance/accessibility, email/push preferences, billing, privacy, security and account actions.
Keep from FTA. Existing settings, notification preferences, billing and centralized entitlement system.
Rebuild for FIC. Add tenant-aware branding/preferences, youth/guardian controls and accessibility settings.
Connects to. Profile, Admin, Notifications.
3.31 Help / Support
Purpose. Resolve product and learning-support issues.
UX. Search help, FAQs and contextual support chat. Escalation creates/links to a support record.
Keep from FTA. Existing Help route, API-backed help chat, admin support tooling and CRM support views.
Rebuild for FIC. Brand per tenant and distinguish product support from Kai's educational role.
Connects to. CRM, Profile.
4. Admin + CRM UX
This is one of the strongest systems to preserve. The existing app already has admin home, users, courses, live sessions, community, announcements, learning drafts, shop and a CRM spanning leads, members, families, campaigns, drips, challenge, funnel, pipeline and support. For FIC, this should become the operating console for both the flagship brand and licensed institutions.
4.1 Admin Home
Purpose. Give operators a single operational snapshot.
UX. Dashboard for active learners, new members/leads, family/class activity, lesson completion, live sessions, community moderation, support and revenue/access alerts.
Keep from FTA. Existing /admin home and underlying operational data.
Rebuild for FIC. Add tenant selector and role-specific dashboard modules.
Connects to. All admin modules.
4.2 Users / Members
Purpose. Search, inspect and manage learner accounts.
UX. Table/search with tenant, role, membership, family/class, activity, progress and access status. Member detail opens a 360-degree view.
Keep from FTA. Existing admin users and CRM member pages.
Rebuild for FIC. Unify account, learning, family, subscription and support context.
Connects to. Families, CRM, Progress, Entitlements.
4.3 Family CRM
Purpose. Understand and support a household as one customer unit.
UX. Family detail shows owner, members, subscriptions, engagement, progress, support history and lifecycle status.
Keep from FTA. Existing CRM family detail pages.
Rebuild for FIC. Make household health and learning engagement first-class metrics.
Connects to. Members, Billing, Support.
4.4 Leads / Funnel / Pipeline
Purpose. Manage prospective families, students and institutional leads.
UX. Lead list with source, stage, contact history, next action and conversion status. Funnel views show registration-to-paid conversion.
Keep from FTA. Existing leads, funnel, pipeline and challenge attribution.
Rebuild for FIC. Separate B2C family pipeline from B2B institution pipeline where needed.
Connects to. Campaigns, Drips, Membership.
4.5 Campaigns / Drips

UX. Build segmented email/SMS/push campaigns based on tenant, membership, learner activity, family status, path progress or lifecycle stage.
Keep from FTA. Existing campaigns, drips, automated contacts and campaign send APIs.
Rebuild for FIC. Add learning-triggered segmentation such as inactive learner, streak at risk or lesson-path milestone.

4.6 Course / Curriculum Admin

Keep from FTA. Existing course management, course detail and Learn draft review.
Rebuild for FIC. Expand from course CMS into curriculum/path builder with concept/mastery metadata and tenant overrides.
Connects to. Learn, Video LMS, Question Bank.
4.7 Live Session Admin
Purpose. Schedule and manage classes and recordings.
UX. Create event, instructor, audience, tenant/cohort, linked path/lesson, reminders and recording metadata.
Keep from FTA. Existing live-session administration.

4.8 Community Admin / Moderation
Purpose. Keep community educational, safe and useful.
UX. Review reports, posts, investment ideas, comments, group activity and youth/community access. Pin high-quality research and manage model-portfolio permissions.
Keep from FTA. Existing community and community-watchlist management.
Rebuild for FIC. Add structured-idea moderation, tenant scopes and age-aware controls.

UX. Target by tenant, family/class, membership or role; schedule and track delivery.

4.10 Support CRM

UX. Support queue opens member/family context, subscription/access, recent activity and prior conversations.
Keep from FTA. Existing CRM support and Help tooling.

4.11 Tenant / White-Label Admin
Purpose. Allow licensed organizations to operate their own branded version without code forks.
UX. Configure logo, colors, domain, terminology, enabled modules, curriculum, roles, community visibility, email branding and reporting.
Keep from FTA. The source inventory supports role/mode composition and existing platform infrastructure, but a complete white-label admin is an FIC expansion.
Rebuild for FIC. Build as a first-class admin module from the new architecture.
Connects to. All member/admin surfaces.
5. Infrastructure to Keep Behind the UX
Market-data services: quotes, bars, company data, logos, news, research aggregation and screener services.
Stripe checkout, memberships, webhooks and entitlement/access logic.
Web Push, notification tables, email fallback, digests and live-event jobs.
Kai AI/research infrastructure and user/context memory where appropriate.
Scheduled automation for alerts, news, performance, access expiry and lifecycle sequences - but reorganized around FIC domains.
Existing auth, Supabase data/services, APIs and working state machines that map cleanly to the new product.
6. Features to Keep but De-Prioritize
Shop: preserve capability, but do not make it a core FIC navigation item.
Legacy FTA premium chat/courses/recordings: preserve as a separate premium program or tenant, not as the FIC product identity.
Trading alerts/Kai Watch: the underlying alert engine can survive, but FIC should not lead with trade-alert UX. It can later support educational watch alerts and advanced programs.
Acquisition Challenge funnel: preserve the proven CRM/funnel infrastructure, but FIC's core member product should not be organized around a challenge.
Advanced screener: preserve power-user capability behind a simplified beginner discovery layer.
7. Rebuild Rule
KEEP THE ENGINE. REBUILD THE EXPERIENCE.
The FTA app already contains mature functionality that would be expensive and unnecessary to recreate. The new FIC build should migrate these systems behind a new tenant-aware shell and redesign their member UX around three questions:
Does this help a beginner understand investing?
Does this help a family/class learn or practice together?
Can the same engine be composed for a white-label educational institution?
If yes, keep it. If the capability is useful but the current presentation feels trader-first, FTA-specific or disconnected, preserve the backend/domain logic and replace the page experience.
